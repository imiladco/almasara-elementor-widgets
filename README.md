# ویجت‌های المنتور الماسارا

افزونه مستقل ویجت‌های المنتور برای فروشگاه ووکامرسی الماسارا — جدا از پوسته فرزند.

## نصب

مخزن باید در این مسیر قرار بگیرد:

```
wp-content/plugins/almasara-elementor-widgets/
```

سپس از پیشخوان → افزونه‌ها، **Almasara Elementor Widgets** را فعال کنید.

## نیازمندی‌ها

| مورد | حداقل نسخه | وضعیت |
|---|---|---|
| PHP | ۷.۴ | الزامی |
| وردپرس | ۶.۰ | الزامی |
| المنتور | ۳.۱۳ | الزامی |
| ووکامرس | — | الزامی |
| جت‌انجین | — | **اختیاری** |

جت‌انجین فقط برای یک حالت لازم است: وقتی در ویجت «بخش محصولات» کارت را از
قالب Listing جت‌انجین می‌گیرید. اگر نصب نباشد، پیش‌فرض همان ویجت خودکار روی
«کارت داخلی این افزونه» می‌رود و همه‌چیز بدون جت‌انجین کار می‌کند.

بدون المنتور یا ووکامرس، افزونه خودش را غیرفعال نگه می‌دارد و در پیشخوان
پیام می‌دهد.

## ویجت‌ها

همه در پنل المنتور، دستهٔ «الماسارا».

| ویجت | کار |
|---|---|
| بخش محصولات | عنوان + دکمهٔ مشاهده همه + فیلتر پیلی دسته‌بندی (ایجکس) + اسلایدر کارت محصول |
| قیمت محصول | قیمت فعلی و پیشین، بج تخفیف، پشتیبانی محصول متغیر (کمترین قیمت یا بازه) |
| گالری محصول | چیدمان گرید یا نوار موبایلی + مودال تمام‌صفحه با لود ایجکسی |
| ویژگی‌های محصول | ویژگی‌ها در گرید یا فلکس، با تکمیل خودکار از ویژگی‌های خود محصول |
| توضیحات محصول | توضیحات کامل/کوتاه محصول یا متن دلخواه |
| دیدگاه‌ها | فهرست دیدگاه و پاسخ + فرم ثبت با نکات مثبت/منفی و پیشنهاد |
| سوالات متداول | آکاردئون + خروجی Schema |
| ناوبری لنگری | نوار چسبان با تشخیص بخش جاری |
| اسلایدر هیرو | اسلایدر تمام‌عرض با پارالاکس |

سطر معرفی (عنوان + خط جداکننده + آیکون) بین چند ویجت از یک Trait مشترک
می‌آید تا کنترل‌ها و رفتارشان یکی بماند.

### بخش محصولات

کارت از دو منبع می‌آید:

- **قالب Listing جت‌انجین** — طراحی کارت دست خودتان است، این ویجت فقط
  کوئری و اسلایدر و فیلتر را می‌دهد.
- **کارت داخلی** — تصویر، عنوان، شعار و قیمت، با تب‌های استایل کامل
  (آیتم، تصویر، عنوان، بخش قیمت) که هرکدام حالت عادی و هاور دارند.
  «هاور» یعنی موس روی هر جای کارت، نه فقط روی همان بخش.

فیلترها: فقط محصولات دارای قیمت (با حداقل قیمت اختیاری)، فقط موجود، فقط
دارای عکس شاخص. دسته‌ای که با فیلترهای فعال محصولی ندارد، پیلش نمایش داده
نمی‌شود.

## معماری

```
includes/
  svg.php                    پاک‌سازی SVG با فهرست سفید روی DOM
  responsive.php             خواندن درست کنترل‌های ریسپانسیو المنتور
  product-card.php           مارکاپ کارت محصول داخلی
  product-extras.php         متاباکس سوالات متداول + endpoint ثبت دیدگاه
  product-section/
    settings.php             تنظیمات خام → پیکربندی معتبر و تایپ‌شده
    query.php                کوئری محصولات، فیلترها، کش، رندر کارت
    rest.php                 endpoint فیلتر دسته + بی‌اعتبارسازی کش
  widgets/
    product-section.php      ویجت (فقط اتصال و مارکاپ)
    product-section/         تِریت‌های کنترل‌های محتوا و استایل
    traits/intro-row.php     سطر معرفی مشترک
assets/
  css/almasara-widgets.css   استایل همهٔ ویجت‌ها
  js/                        یک فایل به‌ازای هر ویجت + modal.js مشترک
  vendor/swiper/             فقط برای دو ویجت اسلایدری صف می‌شود
```

هر ویجت با `get_style_depends()` و `get_script_depends()` دارایی‌هایش را
اعلام می‌کند، پس در صفحه‌ای که آن ویجت نیست هیچ فایلی لود نمی‌شود.

## کش

ویجت بخش محصولات خروجی HTML کارت‌ها را در ترنزینت نگه می‌دارد، چون رندر N
قالب المنتوری سنگین‌ترین بخش کار است.

باطل می‌شود با: ذخیرهٔ محصول، تغییر موجودی، ذخیرهٔ صفحه در المنتور، و
پاک‌سازی فایل‌های المنتور.

کلید کش «سبد» دارد تا خروجی بین کاربران متفاوت جابه‌جا نشود — پیش‌فرض
نقش‌های کاربر و واحد پول جاری. برای کاربران واردشده کش کلاً خاموش است.

اگر کارت شما چیز دیگری وابسته به بازدیدکننده نشان می‌دهد (قیمت منطقه‌ای،
کوپن اختصاصی، سبد خرید):

```php
add_filter( 'almasara_ps_cache_bucket', function ( array $bucket ) {
    $bucket['region'] = my_visitor_region();
    return $bucket;
} );

// یا خاموش‌کردن کامل در شرایط خاص
add_filter( 'almasara_ps_may_cache', fn( $may ) => $may && ! my_special_case() );
```

## امنیت

- **SVG** — هر SVG پیش از درج inline با فهرست سفید روی DOM پاک‌سازی می‌شود:
  فقط عنصر و ویژگی‌های شناخته‌شده می‌مانند، پس هر `on*` ساختاراً حذف
  می‌شود. سندی که DOCTYPE یا تعریف موجودیت دارد اصلاً پارس نمی‌شود (XXE و
  انبساط موجودیت). `href` فقط اجازهٔ ارجاع داخلی دارد.
  برای فعال‌کردن آپلود SVG در کتابخانه رسانه از افزونه‌ای مثل Safe SVG
  استفاده کنید.
- **endpoint بخش محصولات** — کلاینت فقط «کدام ویجت» و «کدام دسته» را
  می‌فرستد؛ قالب کارت، تعداد، مرتب‌سازی، فیلترها و مدت کش از تنظیمات
  ذخیره‌شدهٔ همان ویجت روی سرور خوانده می‌شود. دسته هم باید یکی از
  دسته‌های تعریف‌شده در همان ویجت باشد. محدودیت نرخ بر پایهٔ IP دارد.
- **endpoint دیدگاه** — تلهٔ ربات، محدودیت نرخ، و رعایت تنظیمات «فقط
  خریداران» و «امتیاز اجباری» ووکامرس. IP و User Agent ثبت می‌شوند تا
  آکیسمت و سیل‌بندی وردپرس کار کنند.

## توسعه

```bash
php tests/run.php          # تست‌های واحد
php tests/run.php svg      # فقط یک گروه

# تست یکپارچه با ووکامرس واقعی (روی SQLite، بدون نیاز به سرور دیتابیس)
bash tests/integration/setup.sh /tmp/wpint
WP_ROOT=/tmp/wpint/wp php tests/integration/run.php

# تست مرورگری (المنتور + صفحهٔ واقعی + Chromium)
bash tests/e2e/setup.sh /tmp/wpint
npm i -D playwright && npx playwright install chromium
WP_ROOT=/tmp/wpint/wp node tests/e2e/run.mjs
# اگر کروم از پیش نصب است: CHROMIUM_PATH=/path/to/chrome node tests/e2e/run.mjs

find . -name '*.php' -not -path './vendor/*' -print0 | xargs -0 -n1 php -l
npx eslint assets/js -c eslint.config.mjs
phpcs                      # با phpcs.xml.dist
```

CI روی هر push و pull request همین‌ها را اجرا می‌کند
(`.github/workflows/ci.yml`)، روی PHP 7.4 و 8.1 و 8.3.

دو لایه تست هست:

**واحد** (`tests/`) — بدون وردپرس، منطق خالص: پاک‌سازی SVG، حل مقادیر
ریسپانسیو، اعتبارسنجی تنظیمات، محدودیت دستهٔ REST، و پایداری فهرست
کنترل‌ها.

**مرورگری** (`tests/e2e/`) — صفحهٔ واقعی المنتور در Chromium: عرض کارت‌ها،
حرکت واقعی اسلایدر با کلیک، دو ویجت در یک صفحه، چیدمان بدون جاوااسکریپت، و
حالتی که سوایپر کلاس خودش را می‌گذارد ولی اندازه‌گذاری نمی‌کند.

**یکپارچه** (`tests/integration/`) — روی وردپرس و ووکامرس واقعی، چیزهایی
که فقط با دیتابیس معنا دارند: نمایانی کاتالوگ، هر چهار فیلتر، تکراری‌نشدن
محصول متغیر هنگام مرتب‌سازی با قیمت، محاسبهٔ مالیات، انتخاب ارزان‌ترین
گزینه (و کنارگذاشتن گزینهٔ نامرئی)، رفتار کش برای مهمان و کاربر واردشده،
و پاک‌سازی SVG از یک پیوست واقعی. اگر `WP_ROOT` تنظیم نباشد با پیام
راهنما رد می‌شوند، نه شکست.

این لایه دو جور خودش را از نصبِ میزبان جدا می‌کند، چون هر دو یک‌بار باعث
سبز یا قرمزِ دروغین شده بودند:

- **کدِ زیر آزمایش** همیشه از پوشهٔ کاری خوانده می‌شود. اگر افزونه در همان
  نصب فعال باشد (کاری که `tests/e2e/setup.sh` می‌کند)، وردپرس کپیِ داخل
  `wp-content/plugins` را لود می‌کند و تست بی‌صدا کدِ کهنه را می‌سنجد. یک
  mu-plugin کوچک — که خودِ راه‌انداز می‌نویسد و فقط با `AMW_INTEGRATION`
  فعال می‌شود — آن کپی را از فهرست افزونه‌های فعال کنار می‌گذارد. اگر باز
  هم نگیرد، راه‌انداز مسیر واقعیِ کلاس‌ها را می‌سنجد و با خطا می‌ایستد.
- **داده** هم جدا می‌شود: محصولاتی که خودِ تست نساخته موقتاً `draft`
  می‌شوند و در پایان (حتی اگر تستی fatal بدهد) به وضعیت قبلی برمی‌گردند.
  بدون این، هر محصولی که از قبل در نصب باشد assertهای «فقط یک کارت» را
  می‌شکست.

### دربارهٔ `tests/fixtures-controls.txt`

نام هر کنترل المنتور همان کلیدی است که تنظیم کاربر زیرش ذخیره می‌شود.
تغییر یا حذف یک نام یعنی هر صفحه‌ای که از قبل ویجت را دارد آن تنظیم را
بی‌صدا از دست می‌دهد. این فایل عکسِ فهرست فعلی است و تست با آن مقایسه
می‌کند؛ ضمناً نام تکراری، سکشن یا تب بسته‌نشده و تب تودرتو را هم می‌گیرد،
که هر سه پنل المنتور را بی‌صدا خراب می‌کنند.

اگر عمداً کنترلی اضافه یا حذف کردید، فایل را به‌روزرسانی کنید و دلیلش را
در commit بنویسید.

## آنچه هنوز پوشش داده نشده

- تست مرورگری فقط ویجت بخش محصولات را پوشش می‌دهد؛ مودال‌ها و ویرایشگر المنتور هنوز E2E ندارند.
- تست یکپارچه روی SQLite اجرا می‌شود، نه MySQL. برای منطق افزونه کافی است،
  ولی تفاوت‌های رفتاری خاص MySQL را نمی‌گیرد.
- المنتور در تست یکپارچه نصب نمی‌شود؛ منطق ویجت‌ها با یک استاب کمینه
  سنجیده می‌شود، پس یکپارچگی با خودِ المنتور تست نشده است.
- ویجت دیدگاه‌ها فرم خودش را دارد و از فرم استاندارد ووکامرس استفاده
  نمی‌کند، چون کل هدفش فیلدهای نکات مثبت/منفی است. افزونه‌هایی که به
  مارکاپ فرم استاندارد قلاب می‌زنند این فرم را نمی‌بینند.
- CSS همهٔ ویجت‌ها در یک فایل است (~۱۰KB فشرده). با رشد تعداد ویجت‌ها بهتر
  است به هستهٔ مشترک و فایل هر ویجت تقسیم شود.
- بررسی «دستهٔ غیرخالی» به‌ازای هر دسته یک کوئری می‌زند. کش این را می‌پوشاند
  ولی اولین درخواست بعد از باطل‌شدن کش، با ده‌ها دسته سنگین می‌شود.
